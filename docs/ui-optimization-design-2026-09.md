# 抽屉 UI / 交互全面优化 · 设计稿（2026-09）

> 方法：先设计、后动手。本文是本轮优化的唯一设计依据——每项改动按
> 「现状问题 → 设计方案 → 验收标准」组织；实现时逐项对照，不引入本文
> 之外的风格漂移。视觉语言维持既有体系：玻璃 + 靛紫身份色 + 青瓷选中 +
> `DrawerMotion` 动效预设，本轮**不做重设计，只做系统性打磨**。

## 一、头部：信息整合与状态表达（P1 / P2 / P5 / P9）

### 现状
`HeaderView`：中性灰瓷片图标 + 「组名 ▾」菜单 + 孤立灰色计数胶囊 + 右侧
（排序 / 搜索 / 设置 / 收起）。

### 设计
1. **计数融入组名语境**（P1）：去掉计数胶囊的底色，改为紧随组名的三级灰
   等宽文本（`设计冲刺 ▾ 10`）。计数不再是「一个元素」，而是组名的注脚。
2. **计数语义升级为匹配计数**（P5）：搜索激活且有文本时，同一位置改显
   青瓷色等宽 `N/M`（匹配数/分组总数）——沿用选中色系表达「当前视图状态」。
3. **排序按钮显示当前模式**（P2）：按钮图标 = 当前排序模式的专属符号，
   切换时用 symbol replace 动效过渡；菜单项同步加图标提升可扫读性：
   | 模式 | 符号 | 说明 |
   | --- | --- | --- |
   | 最近加入在前 | `clock.arrow.circlepath` | 时间环 |
   | 最早加入在前 | `hourglass` | 沙漏（久远） |
   | 按名称 A–Z | `abc` | 字母序（避开 textformat 系中文渲染陷阱） |
   | 按类型分组 | `square.grid.2x2` | 网格 |
   | 手动顺序 | `line.3.horizontal` | 排序把手同款，语义互指 |
4. **头部图标底**（P9，修订）：~~中性灰底 → 低透明度品牌渐变底~~——实施后用户定稿
   **图标不用紫色**：头部图标保持中性灰底 + primary 符号。品牌紫只用于瞬态反馈与
   角标场景（拖放反馈 / 置顶图钉 / 收起边条把手），头部与搜索 UI 全程无彩色。
   README 身份色描述同步修正。

### 验收
- 无搜索：头部元素从「图标+组名+胶囊+…」变为「图标+组名·计数+…」，少一个描边元素；
- 搜索 `swi`：原计数位置显示青瓷 `1/10`，清空搜索恢复普通计数；
- 切换排序：按钮图标随模式变化且有替换动效；菜单项带图标 + checkmark；
- 明暗两态下品牌图标底不刺眼、与青瓷选中不冲突。

## 二、搜索：消歧与开合（P4）

### 设计
1. 删除搜索胶囊右外侧的「关闭搜索」X 按钮——关闭路径收敛为三条：
   **Esc**（已有）、**再次点击头部的放大镜**、点输入框外（保留键盘焦点语义）。
2. 头部放大镜升级为 toggle：搜索已展开且无文本时点击 = 收起搜索；
   有文本时点击 = 聚焦输入框（不清空）。展开期间图标常亮品牌色（已有）。
3. 输入框内的 `xmark.circle.fill` 清空按钮保留——胶囊内只剩这一个 X，语义唯一。

### 验收
- 搜索胶囊内不再出现两个 X；Esc / 放大镜均能收起搜索；
- 有文本时点放大镜 = 聚焦不清空；无文本时点 = 收起。

## 三、列表：置顶分区与拖入退后（P3 / P6）

### 设计
1. **置顶分区线**（P3）：置顶区与非置顶区都非空时，两区之间画一条
   24pt 内缩的 hairline（opacity ≤0.10）+ 上下各 2pt 呼吸。不加文字标签——
   图钉角标已表义，分隔线只解决「边界在哪」。
2. **置顶角标强化**（P3）：图钉 7→8.5pt（比例 k 随瓷片），描边同步，
   让 42pt 瓷片上的角标从「隐约可见」到「一眼可辨」。
3. **拖入退后感**（P6）：拖入悬停（isDropTargeted）时列表区
   opacity →0.55、scale →0.985（easeOut 0.14s），描边与「松开，放入抽屉」
   徽章不变——内容退后、容器上前，符合「让位给新文件」的心智。
   空态不退后（空态有自己的 targeted 表现）。

### 验收
- 有置顶 + 普通条目时出现分区线；全置顶或无置顶时不出现；
- 拖文件悬停：列表整体轻退后，松手 / 离开后复原，无跳变；
- 分区线不参与命中（allowsHitTesting false），排序拖拽跨线行为不变。

## 四、Toast 让位（P7）

### 设计
撤销 toast / 轻提示出现期间，列表底部 padding 12 → 64（spring 0.35/0.85
随 toast 同步动画），toast 消失后回落。列表与 toast 从「覆盖」变「让位」，
最后一行始终完整可见。

### 验收
- 移除条目后 toast 弹出，最后一行完整滚入视野上方；toast 消失后列表回落；
- 两个 toast 叠加时错位关系维持（notice 仍抬高 44pt）。

## 五、预览卡 footer 与细节（P8 / P10）

1. footer：提示 chips 左侧成组，元信息右侧 + 前置竖向发丝分隔（高度 10pt），
   组间距 10——两组信息各归其位，不再挤作一团。
2. `SortMode.symbol` 全表替换为安全符号（见 §一）。
3. 悬停行内操作钮组：间距 1→4pt，微调呼吸（不动尺寸语义）。

## 六、明确不做（记录取舍）

| 提案 | 不做的原因 |
| --- | --- |
| 行内操作钮从 3 个减到 2 个 | 「另存为」有独立价值，减钮损害可见性；噪音问题靠间距与密度微调缓解 |
| 拖入到具体行的「腾位」动画 | 行级 onDrop 语义已被排序拖拽占用，叠加外部文件判别风险高；整体退后感已够 |
| 自定义滚动条 | 系统 overlay 滚动条在毛玻璃上表现良好，自定义得不偿失 |
| 键盘 type-ahead | 低频场景，收益 / 复杂度比低，后续单独立项 |
| 收起边条 / 设置面板改版 | 上一轮刚定稿 / 系统 Form 形态已达标 |

## 七、验证计划

2. 明暗两态实机截图逐项核对 §一~§五验收标准（注入含置顶 + 多类型条目的测试数据）；
3. 交互自测清单：搜索开合（Esc/放大镜）、匹配计数、排序切换动效、

4. `CHANGELOG.md` 补条目，README「设计」节同步（头部图标底 / 排序状态 / 搜索交互）。

## 九、修订（用户反馈，2026-09-02）

1. **图标与搜索 UI 去紫**：头部图标保持中性灰底 + primary 符号（§一.4 品牌渐变
   底废止——用户定稿「图标不要用紫色」）；搜索胶囊聚焦态从品牌紫描边 + 紫色外
   发光改为**中性石墨描边**（primary 0.30）+ 底色微升，外发光删除；搜索放大镜
   聚焦色与头部放大镜激活态均改 primary。品牌紫此后只用于：拖放反馈、置顶图钉
   角标、收起边条把手 / 计数徽章、搜索命中高亮——全部是瞬态或角标场景，头部与
   搜索 UI 全程无彩色。
2. **头部「收起成边条」按钮移除**：与左缘拉手重复（用户定稿）。收起路径收敛为
   左缘拉手 / 菜单栏 / 全局热键；头部按钮组只剩 排序 · 搜索 · 设置。
3. **排序把手重做「沟槽让位」**（用户反馈：悬停时左缘把手太大太突兀）——
   废弃「毛玻璃芯片浮层盖在瓷片上」的方案（3fbab29 引入），改为：
   悬停时**行内容右移 16pt（紧凑 14pt）让出左缘沟槽**，9.5pt 纤细三横线
   裸图标把手在沟槽里亮起——落在行卡片自身安静的底色上，天然有对比度，
   无芯片 / 无描边 / 无投影，不再覆盖缩略图；「让位」动作本身就是可拖拽的
   暗示，与 D4「内容让位」同一动效语言。命中区靠纵向 padding 扩到全行高，
   视觉体积不增；行体 onDrag 保持，抓把手 / 抓行体都能开排序会话。
   验证：临时常显补丁截图核对（把手居沟槽、不与瓷片重叠、间距舒适）；
   静止态结构上与旧版一致（无沟槽 padding、把手 opacity 0）。
